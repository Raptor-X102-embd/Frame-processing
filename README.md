# FPGA Image Processing — учебный проект

Учебный проект по обработке изображений на SystemVerilog с прицелом на реализацию в FPGA. Цель — шаг за шагом разобраться в конвейерной обработке видеопотока, работе с фиксированной точкой, интерфейсах ввода/вывода данных (SPI, VGA) и в итоге собрать полноценный pipeline на реальной плате.

Сейчас реализован минимальный, но полностью рабочий сквозной путь:
изображение из файла → поток пикселей с VGA-таймингами → оконная обработка 3×3 → инверсия цвета → запись результата обратно в файл.

---

## Что уже есть

### RTL

`rtl/headers/img_pkg.svh` — пакет с типом `pixel_t`:

    typedef struct {
        logic [7:0] R;
        logic [7:0] G;
        logic [7:0] B;
    } pixel_t;

`rtl/src/pixel_stream.sv` — обвязка вокруг обработчика. Принимает поток пикселей активной области кадра вместе с `h_sync_i` / `v_sync_i`, формирует счётчики `h_cnt` / `v_cnt` и разворачивает входной кадр в поток с рамкой-дублем по краям (padding). Именно этот модуль готовит вход для оконного обработчика так, чтобы 3×3 окно всегда было полностью заполнено, включая края изображения.

`rtl/src/proc_img.sv` — оконный обработчик. Внутри:

- `LINE_BUF_AMOUNT = WINDOW_H - 1` строчных буферов (текущая строка не сохраняется — она и так есть в потоке);
- сдвиговый регистр окна `wsr[WINDOW_H][WINDOW_W]`;
- чтение центра окна `wsr[PROC_PIX_Y][PROC_PIX_X]` и применение операции (сейчас — побитовая инверсия `255 - x` по каждому каналу).

### Тестбенч

`tb/tb_top.sv` — самодостаточный тестбенч:

- генерирует VGA-совместимые тайминги 640×480 @ 60 Hz (H: 640/16/96/48, V: 480/10/2/33);
- читает сырой RGB-поток из `images/*.raw`;
- подаёт пиксели в DUT ровно в те такты, когда активна область кадра (look-ahead счётчиков);
- пишет результат в отдельный `.raw` файл по сигналу `valid_o`.

### Python-утилиты

`python/img2raw.py` — конвертирует PNG/JPG в плоский RGB-поток (3 байта на пиксель, row-major, сверху вниз, слева направо).

`python/raw2img.py` — обратная операция. Принимает `.raw` и путь для `.png` (по умолчанию кладёт рядом с исходником). Предупреждает, если размер файла не совпал с 640×480×3.

`python/invert_raw.py` — делает эталонный инвертированный `.raw` из исходного. Нужен для проверки, что DUT выдал именно то, что должен.

`python/compare_inv.py` — побайтово сравнивает два `.raw` и говорит, является ли второй точной инверсией первого. Показывает количество несовпадающих байт, максимальное отклонение и индекс первого расхождения (с указанием пикселя и канала).

## Как это работает end-to-end

1. Изображение кладётся в `images/`, например `lemme_chex.png`.
2. `img2raw.py` превращает его в `lemme_chex.raw`.
3. `tb_top.sv` подаёт его потоком в `pixel_stream` с VGA-таймингами.
4. `pixel_stream` формирует паддинг по краям и отдаёт в `proc_img` непрерывный поток пикселей.
5. `proc_img` в каждом такте держит актуальное окно 3×3 и применяет к центру инверсию.
6. Результат по `valid_o` пишется в `lemme_chex_inv.raw`.
7. `raw2img.py` показывает картинку, `compare_inv.py` — говорит, всё ли точно.

## Архитектурные заметки

### Паддинг

Краевые пиксели дублируются, чтобы окно 3×3 не выходило за пределы изображения. Логика реализована в FSM `hp_state` / `vp_state` в `pixel_stream.sv`. На выходе `pixel_proc` в потоке появляется `(H_ACTIVE_PIX + 2) × (V_ACTIVE_LINES + 2)` пикселей, из которых `proc_img` берёт ровно `H_ACTIVE_PIX × V_ACTIVE_LINES` валидных.

## Roadmap

### Ближний план

- **Fixed-point арифметика.** Сейчас всё в 8-битном беззнаковом RGB. Следующий шаг — переход на `logic signed [15:0]` или Q-формат для фильтров. Нужно научиться: представлять коэффициенты, обрезать/насыщать результат обратно в 8 бит, работать со знаком.
- **Новые операции.** После fixed-point — градиентные фильтры, пороги, возможно, цветокоррекция. Всё это укладывается в тот же интерфейс `proc_img` (окно 3×3 на входе, один пиксель на выходе).

### Средний план

- **VGA-вывод.** Логика таймингов уже реализована в тестбенче, её нужно вынести в отдельный RTL-модуль и подать на физический ЦАП (R-2R) или на VGA-разъём через резисторную сборку. Это позволит видеть результат обработки в реальном времени на мониторе.
- **Интеграция в FPGA.** Выбрать плату (что-то из Cyclone / Artix / Lattice), развести clock domain, подключить PLL, написать топовый модуль с привязкой к пинам. Первая цель — прогнать инверсию на живом видео.
- **Ввод данных.** Разобраться с SPI (как основной кандидат для приёма кадров от внешнего источника) или с чтением из внешней SRAM/SDRAM. Пока не решено, какой протокол использовать.

## Структура репозитория

    rtl/
      headers/
        img_pkg.svh        — пакет с pixel_t
      src/
        pixel_stream.sv    — VGA-тайминги + паддинг + обвязка обработчика
        proc_img.sv        — оконный обработчик 3×3
    tb/
      tb_top.sv            — тестбенч с VGA-генератором и файловым I/O
    python/
      img2raw.py           — PNG/JPG -> raw RGB
      raw2img.py           — raw RGB -> PNG
      invert_raw.py        — эталонная инверсия raw
      compare_inv.py       — побайтовое сравнение с проверкой инверсии
    images/
      lemme_chex.png       — исходник
      lemme_chex_inv.raw   — выход DUT
    build/
      wave.vcd             — дамп сигналов

---

## Что пока не сделано

- Нет RTL-модуля для VGA-вывода (тайминги есть только в TB).
- Нет синтезируемого топового модуля и constraint-файла.
- Нет интерфейса ввода данных с внешнего источника.
- Fixed-point не начат.
- Параметризация окна не протестирована за пределами 3×3.

Это учебный проект, поэтому структура и API модулей могут меняться по мере освоения новых тем.
